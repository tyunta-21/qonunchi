# ADR-0002. Переписывание вопроса в юридические термины

**Статус:** принято

## Контекст

Пользователь пишет «меня уволили без причины, что делать», а в Трудовом кодексе это «расторжение трудового договора по инициативе работодателя». Лексический поиск ([ADR-0001](0001-sqlite-fts5-instead-of-vector-db.md)) по бытовым словам находит не те статьи.

## Решение

Перед поиском делается короткий дешёвый вызов LLM (`KW_PROMPT` в `app/llm.py`): вернуть 4–10 слов так, как звучат заголовки статей, и не добавлять особые категории людей, если их нет в вопросе. Затем ищем **и** по переписанному запросу (вес 1,0), **и** по исходному (вес 0,9), объединяем кандидатов.

- Поиск по исходному вопросу запускается параллельно с вызовом LLM, поэтому задержка почти не растёт.
- Ответ малого вызова ограничен 80 токенами.
- Результат кэшируется в `api.db` по ключу `провайдер | язык | вопрос | версия промпта`: повтор вопроса даёт те же источники, а смена промпта автоматически сбрасывает кэш.

## Последствия

- ➕ Заметно выше Hit@5 на бытовых вопросах.
- ➕ Если LLM недоступна, поиск по исходному вопросу всё равно работает.
- ➖ Лишние ~100–300 токенов и одна сетевая задержка на вопрос (в кэше — ноль).
